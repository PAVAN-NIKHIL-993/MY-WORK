# Build

## Commands

```bash
npm run build     # tsc --noEmit && vite build
npm run preview   # serve dist/ on :4173
```

`build` fails fast on a type error because `tsc --noEmit` runs first. Vite then
transpiles without type-checking (esbuild), which is why the two steps are
separate.

Totals: **~390 kB raw / ~115 kB gzip** for the application including React, plus

No chunk splitting is configured — the app is a single entry and a single route
graph, so splitting would add requests without improving perceived load.

## Configuration (`vite.config.ts`)

| Setting | Value | Reason |
| --- | --- | --- |
| `plugins` | `@vitejs/plugin-react` | JSX, Fast Refresh |
| `resolve.alias` | `@` → `src` | Mirrors `tsconfig.paths`; avoids `../../..` chains |
| `base` | `VITE_BASE_PATH` or `/` | Deploy under a sub-path |
| `server.host` | `true` | Bind `0.0.0.0` for proxy/LAN previews |
| `build.target` | `es2022` | Native modules, optional chaining, top-level await not used |
| `test.environment` | `jsdom` | Component tests |
| `test.setupFiles` | `src/test/setup.ts` | jest-dom matchers + platform mocks |
| `test.css` | `false` | CSS is not parsed during tests except the token test, which reads the file directly |

## Assets

| Type | Handling |
| --- | --- |
| CSS | One bundle, minified; no preprocessor |
| Fonts | System stack — no font files, no FOUT, no third-party request |
| Images | None (all iconography is inline SVG in React) |
| Favicon | Inline SVG data URI in `index.html` |
| JSON samples | Bundled as TypeScript strings in `src/samples` |

Nothing is fetched at runtime, so the build has no external asset URLs to keep
alive.

## Bundle composition (approximate)

| Part | Share |
| --- | --- |
| React + ReactDOM | ~45% of the JS |
| Icons (30 inline SVG path definitions) | ~10% |
| Screens, components, styles helpers | ~35% |
| Engine + storage + selectors | ~10% |

No code-splitting opportunity has a user-visible benefit at this size; the whole
bundle is smaller than one typical hero image.

## Build determinism

* Lockfile committed; `npm ci` reproduces the tree.
* Vite hashes asset filenames by content.
* `dist/` is git-ignored — it is an artefact, not source.
* **Source maps are generated by default** (`build.sourcemap`), producing a
  ~1.49 MB `.js.map` that contains the full original source. This is deliberate —
  a deployed build should be debuggable — but it publishes the source, so set
  `VITE_SOURCEMAP=false` when that trade-off is not acceptable.

## Environment-specific builds

```bash
# Deploy under a sub-path
VITE_BASE_PATH=/a11y-workbench/ npm run build

# Smaller finding cap for a demo
VITE_MAX_FINDINGS_PER_SCAN=100 npm run build
```

## Verifying a build

```bash
npm run preview
```

Then check: the app loads with no console errors, the theme toggle works, a sample
audit produces findings, and `View Source` on the page shows hashed asset paths.

```bash
npx vite preview --port 4174   # alternative port
```

## Common build problems

| Problem | Cause | Fix |
| --- | --- | --- |
| `TS2307: Cannot find module '@/…'` | Alias missing in `tsconfig.json` `paths` | Add it in both `vite.config.ts` and `tsconfig.json` |
| Build succeeds, app 404s on assets | Wrong `base` for the hosting path | Set `VITE_BASE_PATH` |
| `Rollup failed to resolve import` | Case mismatch in an import path (works on macOS, fails on Linux) | Fix the casing |
| Stale output | Browser cache | Hashed filenames prevent this; hard-reload if you replaced `index.html` |
