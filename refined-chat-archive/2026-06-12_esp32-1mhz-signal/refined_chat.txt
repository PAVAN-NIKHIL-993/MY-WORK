Yes. An **ESP32 can produce a 1 MHz signal** quite easily.

A few ways:

### 1. LEDC PWM (Easiest)
ESP32's hardware PWM can generate 1 MHz square waves.

```cpp
const int pin = 18;

void setup() {
  ledcAttach(pin, 1000000, 1);
}

void loop() {
}
```

Or with the traditional API:

```cpp
const int pin = 18;
const int channel = 0;

void setup() {
  ledcSetup(channel, 1000000, 1);
  ledcAttachPin(pin, channel);
  ledcWrite(channel, 1);
}

void loop() {
}
```

At **1 MHz**, don't expect high resolution. Physics has opinions, unfortunately.

---

### 2. Direct GPIO Toggle
Not recommended.

```cpp
digitalWrite(pin,HIGH);
digitalWrite(pin,LOW);
```

`digitalWrite()` is far too slow for a stable 1 MHz output.

---

### 3. Hardware Timers
Can generate precise frequencies using interrupts, but PWM hardware is usually the better choice.

---

### 4. I2S / RMT / Clock Output
ESP32 peripherals can generate frequencies much higher than 1 MHz.

Some GPIOs can even output internal clocks in the tens of MHz range.

---

### Reality Check
- 1 MHz = 1 µs period
- 500 ns HIGH
- 500 ns LOW

Use an oscilloscope to verify it. A multimeter will stare blankly at 1 MHz and report something that belongs in a fantasy novel.

If you're trying to generate 1 MHz for:
- Clock signal
- Stepper motor driver
- Ultrasonic circuit
- RF experiment
- Function generator

the best method differs slightly.

Technically **yes, but not in the way most people imagine**.

The ESP32 ADC can sample at around:

- **~6 kSPS to 100 kSPS** with standard `analogRead()`
- **Hundreds of kSPS** using DMA/I2S ADC mode
- Up to about **1-2 MSPS (mega-samples/sec)** under ideal conditions on some ESP32 variants

The catch is the **Nyquist theorem**:

genui{"math_block_widget_always_prefetch_v2":{"content":"f_{sample} \\geq 2f_{signal}"}}

To accurately reconstruct a **1 MHz sine wave**, you'd need **more than 2 MSPS**, and realistically **5-10 MSPS** for decent measurements.

So:

| Signal | ESP32 ADC |
|----------|----------|
| 1 MHz square wave detection | Possible |
| 1 MHz frequency measurement | Possible |
| 1 MHz pulse counting | Easy |
| 1 MHz waveform capture | Poor |
| 1 MHz sine wave reconstruction | Not practical |

### If you only need frequency
Don't use the ADC.

Feed the signal into a GPIO and use:
- Pulse Counter (PCNT)
- Frequency counting with timers
- Input Capture

ESP32 can count signals in the MHz range much more reliably than it can sample them. Humans keep trying to use ADCs as universal problem-solvers, like duct tape with a degree in electronics.

### Example
If your signal is:

- 0-3.3 V square wave
- 1 MHz

You can count pulses for 1 second:

```cpp
Frequency = PulseCount / Time
```

and get very accurate frequency measurements without touching the ADC.

What exactly is the 1 MHz signal?
- Square wave?
- Sine wave?
- PWM?
- FG/tachometer output?
- RF signal?

That determines whether you need ADC sampling, pulse counting, or something more specialized.

Yes. **An ESP32 can detect, count, and measure a 1 MHz signal much more easily than it can ADC-sample it.**

Methods:

### 1. Pulse Counter (PCNT) ✅
Best for frequency counting.

- Counts rising/falling edges in hardware
- Very low CPU load
- 1 MHz is generally no problem
- Can measure RPM, clocks, pulse trains, FG outputs

---

### 2. GPIO Interrupts ⚠️
Possible, but not ideal.

At 1 MHz:

- 1,000,000 interrupts/sec
- CPU will be overwhelmed
- Missed pulses likely

Avoid this method.

---

### 3. Hardware Timers + Pulse Counter ✅
Professional approach.

- Count pulses during a precise time window
- Calculate frequency

Example:

```text
1,000,000 pulses in 1 second
=
1 MHz
```

---

### 4. RMT Peripheral ✅
ESP32's RMT can measure pulse widths and frequencies accurately.

Useful for:
- PWM analysis
- Duty cycle measurement
- High-speed pulse trains

---

### 5. MCPWM Capture ✅
Can timestamp signal edges using dedicated hardware.

Useful for:
- Frequency measurement
- Duty-cycle measurement
- Motor feedback signals

---

### Rough Capability

| Method | 1 MHz |
|----------|----------|
| ADC waveform capture | ❌ Poor |
| PCNT | ✅ Good |
| RMT | ✅ Good |
| MCPWM Capture | ✅ Good |
| Interrupts | ⚠️ Not recommended |
| External counter IC | ✅ Excellent |

If the signal is a clean 3.3 V square wave, the ESP32 can absolutely tell you:

- Frequency
- Pulse count
- Period
- Duty cycle

at 1 MHz. What it cannot do well is act like an oscilloscope and faithfully digitize the entire 1 MHz waveform. For that, you need a faster ADC or dedicated acquisition hardware. Nature has a habit of charging extra whenever you want both speed and accuracy.

For reading a **1 MHz digital signal**, most ESP32 GPIOs can do it, but some choices are better than others.

### Good GPIOs for 1 MHz input
- GPIO 4
- GPIO 5
- GPIO 18
- GPIO 19
- GPIO 21
- GPIO 22
- GPIO 23
- GPIO 25
- GPIO 26
- GPIO 27
- GPIO 32
- GPIO 33

These work well with:
- PCNT
- RMT
- MCPWM Capture
- Timer-based frequency measurement

### Avoid
- GPIO 6-11 (connected to flash memory)
- GPIO 34-39 if you need internal pullups/pulldowns (input-only pins)
- Boot-strapping pins if possible:
  - GPIO 0
  - GPIO 2
  - GPIO 12
  - GPIO 15

They can affect boot behavior if driven incorrectly during startup. Because apparently even microcontrollers enjoy keeping a few landmines around for entertainment.

### For ESP32 DevKit V1
I usually pick:
- GPIO 18
- GPIO 19
- GPIO 21
- GPIO 22
- GPIO 23

for high-speed digital signals.

### Important
The input signal must be:
- 0-3.3 V logic (preferred)
- Not exceed 3.6 V

If your 1 MHz signal is 5 V, use:
- Voltage divider, or
- Logic level shifter

before connecting it to the ESP32.

If you're using an ESP32 DevKit V1 and want to measure the frequency of a 1 MHz square wave, GPIO 18 with the PCNT peripheral is a solid choice.
