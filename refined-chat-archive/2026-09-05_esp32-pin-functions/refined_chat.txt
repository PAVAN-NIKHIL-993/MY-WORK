# The important part: what ELSE can these pins do?

The labels in your picture aren't exclusive.

For example:

### GPIO23

The picture says:

> MOSI / VSPI_MOSI

That does **NOT** mean GPIO23 can only be MOSI.

You can use GPIO23 as:

- Digital output
- Digital input
- PWM
- SPI MOSI
- I2C SDA/SCL
- UART TX/RX
- RMT
- Pulse generation
- Servo control
- WS2812/NeoPixel data
- etc.

The ESP32's **GPIO matrix** allows many peripheral signals to be internally routed to different GPIOs.

---

# 1. PWM

For your projects, this is particularly useful.

Almost every normal output-capable GPIO can generate PWM using **LEDC**.

For example:

```text
GPIO4   → PWM
GPIO16  → PWM
GPIO17  → PWM
GPIO18  → PWM
GPIO19  → PWM
GPIO21  → PWM
GPIO22  → PWM
GPIO23  → PWM
GPIO25  → PWM
GPIO26  → PWM
GPIO27  → PWM
GPIO32  → PWM
GPIO33  → PWM
```

You aren't restricted to a "PWM pin."

So a motor controller could use:

```text
GPIO17 → Motor PWM
GPIO16 → Motor direction
```

or

```text
GPIO25 → Motor PWM
```

etc.

---

# 2. UART

The ESP32 has multiple UART peripherals.

Typical configuration:

### UART0

```text
GPIO1 → TX0
GPIO3 → RX0
```

This is normally used by:

- USB programming
- Serial Monitor
- boot messages

So I generally **wouldn't waste GPIO1/3 on a permanent sensor**.

You can technically remap UART signals elsewhere.

For example:

```text
UART2 TX → GPIO17
UART2 RX → GPIO16
```

This is why:

```text
GPIO16 + GPIO17
```

are very useful for modules such as:

- GPS
- GSM
- DFPlayer
- serial sensors
- RS485
- another ESP32

---

# 3. I2C

The traditional configuration is:

```text
GPIO21 → SDA
GPIO22 → SCL
```

That's the configuration I recommend unless you have a reason to change it.

For example:

```text
GPIO21 → MAX30102 SDA
GPIO22 → MAX30102 SCL
```

You can put multiple I2C devices on the same bus:

```text
GPIO21 ───── SDA
             │
        MAX30102
        SHT31
        MPU6050
        MCP4725
             │
GPIO22 ───── SCL
```

provided their addresses don't conflict.

---

# 4. SPI

The board image shows the common VSPI mapping:

```text
GPIO23 → MOSI
GPIO19 → MISO
GPIO18 → SCK
GPIO5  → CS
```

So:

```text
23 = MOSI
19 = MISO
18 = SCK
5  = CS
```

This is excellent for:

- SD card
- TFT display
- LoRa
- Ethernet
- ADC
- DAC
- SPI flash
- other high-speed peripherals

And CS can usually be assigned to another GPIO too.

---

# 5. DAC

This is one of the special features you don't want to overlook.

Only **two GPIOs have true analog DAC output**:

```text
GPIO25 → DAC1
GPIO26 → DAC2
```

They can produce approximately:

```text
0 V → 3.3 V
```

with 8-bit DAC resolution.

So:

```text
GPIO25 → analog output
GPIO26 → analog output
```

Useful for:

- analog reference
- simple waveform generation
- audio experiments
- analog control voltage

This is different from PWM.

---

# 6. ADC

### ADC1

These are your **best ADC pins**, particularly if you're using Wi-Fi:

```text
GPIO36
GPIO39
GPIO34
GPIO35
GPIO32
GPIO33
```

ADC1:

```text
GPIO36 → ADC1_CH0
GPIO37 → ADC1_CH1*
GPIO38 → ADC1_CH2*
GPIO39 → ADC1_CH3
GPIO32 → ADC1_CH4
GPIO33 → ADC1_CH5
GPIO34 → ADC1_CH6
GPIO35 → ADC1_CH7
```

`GPIO37/38` aren't exposed on the board shown.

### Very important

For ESP32 + Wi-Fi:

**Prefer ADC1.**

ADC2 has hardware interaction with the Wi-Fi subsystem on the classic ESP32.

So if you're building a Wi-Fi device and need reliable analog measurements:

```text
GOOD:
GPIO32
GPIO33
GPIO34
GPIO35
GPIO36
GPIO39
```

rather than relying on ADC2.

This matters for things like:

- NTC
- potentiometer
- battery voltage
- analog pressure sensor
- analog current sensor
- LDR
- analog gas sensor

---

# 7. Touch sensing

The ESP32 also has capacitive touch inputs.

From your board:

```text
GPIO32 → Touch 9
GPIO33 → Touch 8
GPIO27 → Touch 7
GPIO14 → Touch 6
GPIO12 → Touch 5
GPIO13 → Touch 4
GPIO4  → Touch 0
GPIO2  → Touch 2
GPIO15 → Touch 3
```

You can therefore make things such as:

```text
Copper pad
   ↓
GPIO4
   ↓
ESP32
```

and detect a finger without a mechanical switch.

---

# 8. RMT

This is especially interesting for your embedded projects.

ESP32 RMT is excellent for precise pulse timing.

It can be used for:

- WS2812 LEDs
- IR transmit/receive
- servo signals
- pulse generation
- ESC signals
- custom protocols

So GPIOs such as:

```text
GPIO4
GPIO16
GPIO17
GPIO18
GPIO19
GPIO21
GPIO22
GPIO23
GPIO25
GPIO26
GPIO27
GPIO32
GPIO33
```

can be used for timing-based output depending on the peripheral configuration.

This is one reason the ESP32 is much more flexible than the pinout diagram suggests.

---

# 9. Servo / ESC

For your previous servo/ESC type applications, you don't need dedicated "servo pins."

For example:

```text
GPIO16 → ESC1
GPIO17 → ESC2
GPIO18 → ESC3
GPIO19 → ESC4
GPIO21 → Servo5
```

can all generate servo-style pulses.

The actual choice should instead consider:

- boot strapping
- SPI/I2C requirements
- UART requirements
- input/output direction
- electrical noise
- whether another peripheral needs the pin

---

# ⚠️ Pins I would treat carefully

This is the part that saves you from three hours of staring at a dead ESP32 while questioning your life choices.

## GPIO0

Boot/strapping pin.

Don't casually attach hardware that forces it LOW during reset.

Used for:

```text
BOOT
FLASH programming
```

Avoid for critical peripherals unless you understand the boot-state requirement.

---

## GPIO2

Also a strapping/boot-related pin.

It can be used normally after boot, but attached circuitry should not interfere with the required startup level.

---

## GPIO5

Strapping pin.

Although it's a perfectly usable GPIO and commonly used as:

```text
VSPI CS
```

be careful with external hardware during reset.

---

## GPIO12

**Particularly important.**

GPIO12 is a strapping pin controlling the ESP32's flash supply configuration.

Avoid forcing it to an inappropriate level during reset.

I would **not choose GPIO12 for a critical external circuit** unless there is a good reason.

---

## GPIO15

Also a strapping pin.

Usable, but again, external circuitry shouldn't interfere with boot configuration.

---

# ⚠️ GPIO34–39

These are special.

```text
GPIO34
GPIO35
GPIO36
GPIO39
```

are:

### INPUT ONLY

You cannot use them for:

```text
LED output
PWM
relay
motor
servo
DAC
```

For example:

```cpp
digitalWrite(34, HIGH);
```

isn't going to magically turn GPIO34 into an output. The silicon has already made that decision for you.

But they are **excellent sensor inputs**.

---

# ⚠️ GPIO6–11

These are not shown as usable header pins on your board.

They are generally connected internally to the ESP32's SPI flash:

```text
GPIO6
GPIO7
GPIO8
GPIO9
GPIO10
GPIO11
```

**Do not use them as normal GPIO.**

This is particularly important because people see GPIO numbers missing from the board and think they've discovered six secret bonus pins. They have not.

---
