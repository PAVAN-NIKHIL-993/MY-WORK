### Engineering personality
This method is **traditional, conservative, and transparent**. Old-school signal hygiene. Accountants love it. Regulators love it. Debuggers love it.

## 2️⃣ Exponential Moving Average (EMA)

### What it really is
- Each new BPM nudges the output
- Old BPMs **never fully disappear**
- Influence decays exponentially

Formula:
```
BPM_out = α * BPM_new + (1 − α) * BPM_out
```

### Behavioral properties

**Pros**
- Extremely light computation  
  One multiply, one add.
- No buffer  
  One variable.
- Very smooth output  
  No step changes.
- Fast response if α is large

**Cons**
- Infinite memory  
  Bad data technically lives forever.
- Harder to reason about  
  You don’t know “how long” a value matters.
- Tuning-dependent  
  Bad α choice ruins behavior.
- Can hide slow drift  
  Especially dangerous in medical-style data.

### Engineering personality
EMA is **modern, elegant, and slightly slippery**. Looks great on plots. Less great when you’re trying to explain *why* a number changed.

### 1️⃣ Reduced I²C polling  
Instead of asking the sensor:

- Fewer I²C transactions
- Slightly lower power usage
- Cleaner bus behavior

This matters in:
- Battery-powered wearables
- Ultra-low-power designs
- Systems sleeping most of the time

### 2️⃣ FIFO-driven sampling discipline  
With INT + FIFO watermark:
- You read samples in **bursts**
- Timing becomes FIFO-driven, not loop-driven
- Less risk of FIFO overflow if loop jitter exists

This helps when:
- MCU is doing many other tasks
- RTOS scheduling introduces jitter

MCU can:
- Sleep
- Wake only on INT
- Read FIFO
- Go back to sleep

- Smartwatches
- Fitness bands
- Coin-cell devices
